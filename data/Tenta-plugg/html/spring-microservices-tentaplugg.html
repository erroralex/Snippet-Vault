Spring Boot Introduktion

Spring Boot är ett ramverk som förenklar skapandet av Java-applikationer genom automatisk konfiguration, inbyggd server och starters-paket. Det bygger på IoC och Dependency Injection.

Inversion of Control (IoC)

IoC innebär att ramverket ansvarar för objektens livscykel — inte du. Spring skapar, kopplar ihop och förstör objekt åt dig via sin IoC-container.

Utan Spring (manuellt)

UserService service = new UserService(
    new UserRepository()
);

Med Spring (IoC)

@Service
public class UserService {
  @Autowired
  private UserRepository repo;
}
Tre steg till IoC: (1) Du skapar klassen → (2) Spring skapar instansen → (3) Spring hanterar beroendena automatiskt.
Dependency Injection (DI) – Konstruktor-injektion

Det finns tre sätt att injicera beroenden. Konstruktor-injektion är best practice — den är testbar, explicit och möjliggör immutabilitet.

// ✅ BEST PRACTICE – Konstruktor-injektion
@Service
public class BookingService {
    private final BookingRepository repo;
    private final EmailService email;

    public BookingService(BookingRepository repo, EmailService email) {
        this.repo  = repo;
        this.email = email;
    }
}

// ⚠️ Fungerar men undvik — svår att testa
@Autowired
private BookingRepository repo;

@Service
public class BookingService {
    private final BookingRepository bookingRepo;

    public BookingService(BookingRepository bookingRepo) {
        this.bookingRepo = bookingRepo;
    }

    // 1. Affärslogik tillhör service, INTE controller
    public Booking createBooking(BookingDto dto) {
        validateBooking(dto);                          // validering
        Booking b = new Booking(dto.getRoomId(), dto.getDate());
        return bookingRepo.save(b);
    }

    // 2. Centralisera felhantering
    public Booking getById(Long id) {
        return bookingRepo.findById(id)
            .orElseThrow(() -> new EntityNotFoundException("Booking not found: " + id));
    }
}

Embedded Tomcat

Spring Boot inkluderar en inbyggd webbserver (Tomcat) — du behöver ingen extern applikationsserver. Kör applikationen direkt med java -jar myapp.jar. Kan bytas mot Jetty eller Undertow.

WAR vs JAR: Med inbäddad Tomcat paketeras allt som en fat JAR (self-contained). WAR används när du deployer till en extern server. Spring Boot rekommenderar JAR.

JPA – Java Persistence API

JPA är en specifikation för persistens i Java. Hibernate är standardimplementationen i Spring Boot. Använder annotationer.

Entity – mappa en klass till databastabellen
@Entity
@Table(name = "employees")
public class Employee {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false, length = 100)
    private String name;

    @Column(unique = true)
    private String email;

    private double salary;

    @ManyToOne
    @JoinColumn(name = "department_id")
    private Department department;

    // Getters, setters, konstruktorer...
}

REST & HTTP

REST (Representational State Transfer) är en arkitekturstil för att designa nätverkstjänster. En REST API kommunicerar över HTTP och hanterar resurser.

REST-principer

Stateless

Ingen sessionsinformation lagras på servern. Varje request innehåller all nödvändig information.

Uniform Interface

Standardiserade HTTP-metoder, URI-er som identifierar resurser.

Client-Server

Klient och server är separerade. Klienten hanterar UI, servern hanterar data.

Cacheable

Responses kan markeras som cachelagringsbara för bättre prestanda.

API-versionering – varför?

När ett API förändras kan befintliga klienter sluta fungera. Versionering gör det möjligt att förändra API utan att bryta befintliga integrationer.

StrategiExempelFördelar / Nackdelar

/api/v2/users		 Enkel, tydlig, cachebarhet
Header-versionering Accept: application/vnd.myapp.v1+json Ren URI men svårare att testa
Parameter-versionering /users?version=1 Enkel men ej cachevänlig

✅ Gör så här

Säkerhet & JWT

Spring Security är ett kraftfullt ramverk för autentisering (vem är du?) och auktorisering (vad får du göra?).

Nyckelbegrepp

Autentisering (AuthN)

Verifiera vem användaren är. Vanliga former: Login + lösenord, JWT-token, OAuth.

Auktorisering (AuthZ)

Avgöra vad en autentiserad användare har rätt att göra. Baseras på roller/rättigheter.

SecurityFilterChain

En kedja av filter som varje HTTP-request passerar igenom. Konfigureras med Java DSL.

SecurityContext

Håller information om den inloggade användaren under request-hanteringen (ThreadLocal).

Spring Security Konfiguration
@Configuration
@EnableWebSecurity
public class SecurityConfig {

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http
            .csrf(csrf -> csrf.disable())            // Disable för stateless REST
            .sessionManagement(sm -> sm
                .sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/auth/**").permitAll() // öppna endpoints
                .requestMatchers("/api/admin/**").hasRole("ADMIN")
                .anyRequest().authenticated()          // allt annat kräver inloggning
            )
            .addFilterBefore(jwtFilter, UsernamePasswordAuthenticationFilter.class);
        return http.build();
    }

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }
}

JWT – JSON Web Token

JWT är ett kompakt, URL-säkert format för att transportera claims (påståenden) mellan parter. Används för stateless autentisering.

JWT-struktur: Header.Payload.Signature

eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9    ← Header (algoritm + typ)
.eyJzdWIiOiIxMjM0NTY3ODkwIiwibmFtZSI6Ikp  ← Payload (claims)
.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQ  ← Signature (header + payload + secret)
JWT Payload – vanliga claims
{
    "sub": "anna@example.com",    // subject (användaren)
    "iat": 1716000000,           // issued at (utfärdad)
    "exp": 1716003600,           // expiration (utgår)
    "roles": ["ROLE_USER", "ROLE_ADMIN"]
}
JSON

Access Token

Kortlivad: 15–30 minuter. Skickas med varje request i Authorization-headern.

Authorization: Bearer <token>

Refresh Token

Längre livslängd: 7–30 dagar. Används för att hämta ett nytt access token utan ny inloggning.

JWT-filter (JwtAuthenticationFilter)
@Component
public class JwtAuthFilter extends OncePerRequestFilter {

    @Override
    protected void doFilterInternal(HttpServletRequest req,
                                       HttpServletResponse res,
                                       FilterChain chain) throws Exception {
        String header = req.getHeader("Authorization");

        if (header != null && header.startsWith("Bearer ")) {
            String token = header.substring(7);
            String username = jwtService.extractUsername(token);

            if (username != null && SecurityContextHolder.getContext().getAuthentication() == null) {
                UserDetails user = userDetailsService.loadUserByUsername(username);
                if (jwtService.isTokenValid(token, user)) {
                    // Sätt upp autentisering i SecurityContext
                    UsernamePasswordAuthenticationToken authToken =
                        new UsernamePasswordAuthenticationToken(user, null, user.getAuthorities());
                    SecurityContextHolder.getContext().setAuthentication(authToken);
                }
            }
        }
        chain.doFilter(req, res);
    }
}

OAuth 2.0

OAuth 2.0 är ett auktoriseringsprotokoll som låter en användare ge en applikation begränsad åtkomst till sitt konto hos en annan tjänst, utan att dela lösenord.

Problemet OAuth löser: Användaren måste logga in på varje tjänst separat. Säkerhetsrisk: varje system/tjänst måste hantera inloggning själv. Skalbarhet: varje system måste hålla koll.
Roller i OAuth 2.0
RollBeskrivningExempel
Resource OwnerAnvändaren som äger datanDu
ClientApplikationen som vill ha åtkomstSpotify, Din App
Authorization ServerHanterar inloggning och utfärdar tokensGoogle, Facebook, GitHub
Resource ServerAPI:t som skyddar datanGoogle API, Spotify API
OAuth 2.0 Flows

Authorization Code Flow – vanligast för webbappar

  1. Användaren klickar "Logga med Google"
  2. Redirect till Google (Authorization Server)
  3. Användaren loggar in och ger tillstånd
  4. Google skickar en code till din app
  5. Din app byter code mot en access token (server-till-server)
  6. Din app anropar Google API med access token

Client Credentials Flow – för tjänst-till-tjänst

  1. Service A skickar client_id + client_secret till Auth Server
  2. Auth Server returnerar access token
  3. Service A anropar Service B med token
Access Token & Refresh Token

Access Token

  • Bevisar att användaren är inloggad
  • Skickas i header: Authorization: Bearer <token>
  • Har expiration (giltighetstid)
  • Har scope (vad man får göra)

Refresh Token

  • Används för att hämta nytt access token
  • Längre livslängd än access token
  • Lagras säkert (server-side)

InloggningEgen (username/password)Extern (Google, FB, etc.)

KomplexitetLägreHögre

    // Skapa logger – en per klass
    private static final Logger logger = LoggerFactory.getLogger(BookingService.class);

    public Booking createBooking(BookingDto dto) {
        logger.info("Startar bokning: {}", dto.getRoomId());   // {} = placeholder
        try {
            Booking b = performBooking(dto);
            logger.info("Bokning {} skapad", b.getId());
            return b;
        } catch (Exception e) {
            logger.error("Bokning misslyckades för rum {}: {}", dto.getRoomId(), e.getMessage(), e);
            throw e;
        }
    }
}

Best Practice – Loggning
  • Använd alltid SLF4J (inte Log4j direkt) — byt implementation utan kodändring
  • Logga på rätt nivå (INFO för flöde, ERROR för fel, DEBUG för detaljer)
  • Använd {} placeholders — undvik strängkonkatenation i loggmeddelanden
  • Logga alltid stacktrace vid exception: logger.error("Meddelande", exception)
  • Inkludera kontext: vad hände, för vem, vilket ID
  • Undvik att logga känslig information (lösenord, personnummer, kortuppgifter)
  • Sätt upp log rotation i produktion
Lombok @Slf4j: Lägg till @Slf4j från Lombok på klassen för att automatiskt få en log-variabel. Sparar boilerplate!
